# Контракт событий и метрик

Таблицы назначений и событий создаются генератором синтетических данных.

## Назначения

`user_id` уникален; `variant` принимает A/B и фиксируется один раз на пользователя.
`assigned_at` — момент назначения до первого поиска; `window_end` — через 7 суток.
`device`, `category`, `prior_sessions` известны до назначения. Категория здесь означает
заранее выбранную категорию интереса, а не выбор после показа изменения.
Все отметки времени в симуляции — UTC без перевода в локальный часовой пояс.

## События

| Поле | Смысл |
|---|---|
| event_id | Ключ идемпотентности; повтор доставки сохраняет ID |
| user_id | Ссылка на назначенного пользователя |
| session_id | Сессия; в симуляции ровно одна на пользователя |
| listing_id | Карточка; обязателен для просмотра и контакта |
| event_name | search, listing_view, contact, complaint |
| event_time | Время действия |
| received_at | Время приёма события |

`contact` — отправленное сообщение или открытие контакта продавца, сведённые
к одному учебному событию. В реальном продукте эти действия нужно согласовать
с владельцем метрики и логировать раздельно. `complaint` — пользовательская жалоба;
в симуляции она может относиться к любому предыдущему взаимодействию в сервисе.

## Расчёт

Основная метрика — уникальные пользователи с contact в закрытом окне
`[assigned_at, window_end]` / все назначенные пользователи. Расчёт после созревания
всех окон. Пользователь с нулём событий остаётся в знаменателе.

Последовательная воронка требует одной сессии, времени «поиск ≤ просмотр ≤ контакт»,
и той же карточки для просмотра и контакта. При равных отметках времени порядок считается
допустимым; в реальном трекинге стоит использовать sequence_id.
Контакт в основной метрике считается независимо от прохождения воронки: потеря событий поиска или просмотра
не должна менять определение целевого действия.

Ограничение — пользователи с жалобой / все назначенные пользователи. Деление только на
сконтактировавших изменило бы состав сравниваемых групп после воздействия.

## Качество и границы

Дедупликация по event_id, проверка различающегося содержимого событий с одинаковым идентификатором, известных пользователей,
отметок времени, типа и идентификаторов. Плохие строки попадают в quarantine.csv.
Код не доказывает полноту логирования. Потери целых событий, неверные часы клиента,
переходы между устройствами и перемешивание групп потребуют отдельных проверок.
Внесённые дубли и 45 дефектных строк добавляются поверх корректного лога.
